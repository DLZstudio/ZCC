## 漏洞 #1: 无参数箭头函数 `() => expr` — "箭头函数地雷"

### 测试代码 (blast_01_empty_arrow.zcc)

```zcc
function main() {
    auto getAnswer = () => 42;
    auto makePoint = () => { x: 0, y: 0 };
    auto add = (a, b) => a + b;
    auto result = add(1, 2);
    print(result);
}
```

### 为什么这个程序应该能编译

箭头函数是 ZCC 明确支持的语法（见 `Token.hpp` 的 `ARROW` token 和 `ArrowFunctionExpr` AST 节点）。`(a, b) => a + b` 的多参数形式工作正常，但 `() => expr` 的无参数形式却在解析器中存在缺陷。

### 为什么被爆破

攻击位置: `src/Parser.cpp:1074`

```cpp
// parsePrimary() 中的箭头函数检测逻辑：
if (!params.empty() && match(TokenType::RIGHT_PAREN) && match(TokenType::ARROW)) {
    // ◆ 当括号为空 () → params.empty() == true
    // ◆ 条件短路为 false → 箭头函数无法被识别!
    // ◆ 回退到普通表达式解析 → 空括号无法构成有效表达式
    // ◆ => 链式 token 被丢弃 → 级联错误!
}
```

缺陷: 条件 `!params.empty()` 将空参数列表排除在箭头函数检测之外。任何合法的 JS/TS 程序 `const f = () => 42;` 在这里都会解析失败。

### 结果

```
Expected expression (at ')')           ← parseExpression() 从 ) 开始就找不到表达式
Expected ')' after expression (at ' =>') ← => 后面的内容全部错位
```

**22 个语法错误 + 3 个 IR 错误 = 完全编译失败**

## 漏洞 #2: `.5` 无前导零浮点数 — "小数点陷阱"

### 测试代码 (blast_02_dot_float.zcc)

```zcc
function main() {
    auto half = .5;
    auto quarter = .25;
    auto negative = -.5;
    auto result = half + quarter;
    print(result);
}
```

### 为什么这个程序应该能编译

`.5`、`.25` 是 C/C++/Java/JS/TS 都接受的合法浮点数写法。在日常编程中极为常见。

### 为什么被爆破

攻击位置: `src/Lexer.cpp:299`

```cpp
// scanNumber() 的数字检测:
if (peekChar() == '.' && isDigit(peekNext())) {
    // ◆ 要求 '.' 前面必须已经读取了整数部分
    // ◆ 单独 "." 在 scanOperator() 中被识别为 DOT token
    // ◆ ".5" = DOT(.) + NUMBER(5) — 完全拆分!
}
```

缺陷: `scanNumber()` 只在 `isDigit(peekChar())` 后才会进入。`.` 字符在没有前导数字时走 `scanOperator()` 路径，产生 `DOT` token。`.5` 变成两个 token: `DOT(.)` + `NUMBER(5)`，在语法层被解析为属性访问 `.5` 而非数字 0.5。

### 结果

```
Expected expression (at ' .')         ← DOT 后面期待属性名，却看到 5
Expected ';' after variable declaration (at '5')
```

**6 个语法错误 = 完全编译失败**

## 漏洞 #3: 字符串键对象字面量 — "JSON陷阱"

### 测试代码 (blast_03_string_key_obj.zcc)

```zcc
function main() {
    auto config = {
        "name": "ZCC",
        "version": "0.2",
        "features": ["ir", "optimizer"]
    };
    auto name = config.name;
    print(name);
}
```

### 为什么这个程序应该能编译

JSON 风格的对象字面量 `{"key": value}` 是 JavaScript/TypeScript 的标准语法。ZCC 语法与 JS 高度相似。

### 为什么被爆破

攻击位置: `src/Parser.cpp` `parseObjectLiteral()` (第 ~257 行)

```cpp
// 对象属性期望是 IDENTIFIER:
auto key = advance();  // 期望 TokenType::IDENTIFIER
// ◆ "name" 是 STRING token, 不是 IDENTIFIER
// ◆ expect() 失败 → 级联错误
```

缺陷: `parseObjectLiteral()` 仅支持 `{ ident: val }` 形式的对象字面量。`{ "str": val }` 的字符串键完全不被支持。解析器遇到 `STRING` 类型时无法匹配 `IDENTIFIER` 预期。

### 结果

```
Expected property name (at '"name"')     ← STRING 不匹配 IDENTIFIER
Expected '}' after obj properties       ← 对象解析中断
```

**28 个语法错误 + 2 个 IR 错误 = 完全编译失败**

## 漏洞 #4: for-each 循环 — "遍历失灵"

### 测试代码 (blast_04_foreach.zcc)

```zcc
function main() {
    auto numbers = [10, 20, 30, 40, 50];
    auto sum = 0;
    for (each n in numbers) {
        sum += n;
    }
    print(sum);
}
```

### 为什么这个程序应该能编译

`for (each ... in ...)` 是 ZCC 明确在 `Token.hpp` 中定义的语法关键字 (`EACH`, `IN`)。这是语言规范的一部分。

### 为什么被爆破

攻击位置: `src/Parser.cpp` `parseForStatement()` (第 ~490 行)

```cpp
// for 语句的解析逻辑：
expect(TokenType::LEFT_PAREN, "Expected '(' after 'for'");
// 解析初始化: auto i = 0;
auto initializer = parseStatement();  
// ◆ 这里 parseStatement() 遇到 'each' keyword
// ◆ 'each' 不是 AUTO/CONST/IF/FOR... → 当作表达式
// ◆ parseExpression() 不知道如何处理 'each' → 失败
```

缺陷: `parseForStatement()` 中的 `parseStatement()` 只处理变量声明、if、for、while、return、break、continue、try、throw、switch 和表达式。`each` 关键词不在这些分支中，被当作普通表达式处理，导致解析失败。

### 结果

```
Expected expression (at 'each')         ← each 关键词未被正确识别
Expected ';' after initializer (at 'n')
Expected ';' after condition (at 'in')
```

**8 个语法错误 + 6 个 IR 错误 = 完全编译失败**

## 漏洞 #5: 赋值链 — "沉默杀手"

### 测试代码 (blast_05_assign_chain.zcc)

```zcc
function main() {
    auto x = 0;
    auto y = 0;
    auto z = 0;
    x = y = z = 42;
    print(x);
    print(y);
    print(z);
}
```

### 为什么这个程序应该能编译

`a = b = c = value` 是 C/C++/Java/JS 中完全合法的右结合赋值链。ZCC 的 `parseAssignment()` 使用递归调用（`auto value = parseAssignment()`）已经实现了右结合解析。

### 为什么被爆破

攻击位置: `src/midend/IRGenerator.cpp`

```
语法层: ✅ 通过 — 解析器生成了正确的嵌套 AssignExpr AST
IR 层:  ❌ 失败 — IRGenerator 在处理嵌套赋值 IR 指令时崩溃
```

缺陷: 语法解析成功但 IR 生成失败。`IRGenerator` 的 `visitAssignExpr()` 不支持嵌套的赋值表达式/或生成赋值指令时出现异常。

### 结果

```
[IR ERRORS] (6)                         ← 解析通过但 IR 全灭
```

**0 语法错误但 6 个 IR 错误 — 静默编译失败**

## 根本原因总结

1. **parsePrimary() 中 `!params.empty()` 条件阻止空箭头函数识别** — 这是最简单的修复：改为 `match(RIGHT_PAREN) && match(ARROW)` 即可

2. **scanNumber() 不支持无前导零的 `.5` 格式** — 需要在 `scanOperator()` 的 `.` 分支中增加前瞻

3. **parseObjectLiteral() 只处理 IDENTIFIER 属性名** — 需要增加 STRING 类型支持

4. **parseForStatement() 不处理 each/in 关键词** — 需要在 for 解析中增加 EACH 分支

5. **IRGenerator 功能不完整** — 赋值链、闭包、中英混合、异常处理的 IR 指令生成未实现

---

## 结论

ZCC v0.2 在**基础功能**（简单算术、变量声明、基本控制流、简单函数）上表现良好，但对于**真实世界的常用编程模式**（箭头函数、JSON风格对象、for-each遍历、赋值链、闭包）存在严重缺陷。

**8/8 合法程序的编译失败率为 100%。**

关键问题集中在两个位置：
- `src/Parser.cpp:1074` — 箭头函数空参数检测
- `src/Lexer.cpp:299` — 浮点数解析
