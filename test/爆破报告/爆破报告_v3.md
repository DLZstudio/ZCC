## 新发现漏洞 #1: `x => body` 单参数箭头函数无法识别

### 测试代码 (blast3_07_combo.zcc)
```zcc
auto square = x => x * x;
```

### 症状
```
Expected ';' after variable declaration (at ' =>')
Expected expression (at ' =>')
Expected ';' after expression (at 'x')
```

### 根因定位 (源码级 Bug)

`src/Parser.cpp` `parsePrimary()`:

```
第 1049 行: match(TokenType::IDENTIFIER) → 立即消耗 'x', 返回 IdentifierExpr
  ...
第 1130 行: check(TokenType::IDENTIFIER) → 检测单参数箭头函数
                                        → 但 'x' 已在 1049 被消耗!
                                        → 这段代码是死代码!
```

**词法层 `x => y` 被解析流程:**
1. `match(IDENTIFIER)` → 消耗 `x` ✅ (不应该!)
2. 返回 `IdentifierExpr("x")` 
3. `parseCall()` 中后续检查遇到 `=>` → 无法识别
4. 报错: "Expected ';' after expression"

**死代码区域** (`Parser.cpp:1130-1159`) — 箭头函数简写检测永远无法触发。

## 新发现漏洞 #2: `...args` 剩余参数词汇错误

### 测试代码 (blast3_10_rest_params.zcc)
```zcc
function sum(...args) {
    ...
}
```

### Token 流实证
```
DOT(.) | DOT(.) | DOT(.) | IDENTIFIER(args)
```

Lexer 将 `...` 分解为 3 个独立的 `DOT(.`) token！

### 症状
```
Expected parameter name (at '.')
Expected ')' after parameters (at '.')
Expected '{' before block (at '.')
...
17 个级联错误
```

### 根因定位

`src/Lexer.cpp:scanOperator()`:
```
case '.':
    if (isDigit(peekChar())) { /* .5 浮点 (已修复) */ }
    return makeToken(TokenType::DOT);   // ← 永远只返回 DOT!
```

Lexer 的 `...` → `DOT_DOT_DOT` 转换完全缺失。`...` 在 Lexer 层面根本没有被识别为单个 token。

**影响:** 所有 `...args` 语法（剩余参数、数组展开、对象展开）都无法工作。

## 新发现漏洞 #3: `每个...在...中` 中文 for-each 语法不完整

### 测试代码 (blast3_08_cn_each.zcc)
```zcc
循环 (每个 n 在 arr 中) {
    sum += n;
}
```

### 症状
```
Expected ')' after for-each (at '中')
Expected '{' before block (at '中')
```

### 原因

`Keywords.hpp` 中 `中` 有定义但**未注册**到关键词映射表中：
- `inline const std::string 中 = "中";` ✅ (常量存在)
- `keywordMap_` 中无 `CNKeywords::中` 映射 ❌ (缺失)

结果: `中` 被当作普通标识符 token，`parseForEachStatement` 解析 `n 在 arr` 后遇到 `中` → 意料之外的 token → 错误。

## 新发现漏洞 #4: switch/case 全链路 IR 失败

### 测试代码 (blast3_01_switch.zcc)
```zcc
function main() {
    auto val = 2;
    auto result = 0;
    switch (val) {
        case 1: result = 10; break;
        case 2: result = 20; break;
        default: result = 0;
    }
    print(result);
}
```

### 结果
```
Parser: 0 errors ✅ (语法层通过)
IR:     9 errors ❌ (IR 层全灭)
```

**9 个 IR 错误全部是 `Undefined variable`** — IRGenerator 不处理 switch 块的变量作用域。

## 结论

ZCC v0.2 编译器在**语法层**已经有明显改善（4 个致命漏洞在第二轮修复）。但在**IR 生成层**存在大量系统性缺失（switch、自增减、中文完整语法、命名空间、类型运算），所有这些都阻挡了合法程序的编译。

**第三轮核心发现:**
- **`x => body` 单参数箭头** — `parsePrimary()` 中标识符匹配在箭头检测之前（死代码）
- **`...args` 展开语法** — Lexer 完全不支持 `DOT_DOT_DOT` token
- **`中` 关键词** — 定义了但未在映射表注册
